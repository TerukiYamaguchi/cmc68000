# MC68010

## 1. 目的と対象範囲

この文書は `MC68K_MODEL_68010` の、MC68000 からの差分を定義する。対象は追加制御レジスタ、
追加命令、format 付き例外 frame、group 0 例外の再開、cycle profile である。

MC68000 と共通の整数命令、実効アドレス、バス境界、基本的な割り込み契約は
[MC68000](cpu_68000.md) を参照する。

## 2. 実装状態

MC68010 は `mc68k_create_model(bus, MC68K_MODEL_68010)` で生成する。FPU 構成は
`MC68K_FPU_NONE` だけを受理する。

VBR、SFC、DFC、MOVEC、MOVES、RTD、format 0／8 frame、RTE による group 0 再開を実装する。
MC68020 以降の full-format EA、bit field、MMU、cache は対象外である。

## 3. 設計の要点

| 決定 | 理由 | 影響 | 検証 |
| --- | --- | --- | --- |
| 68010 差分は基本 decode table へ上書き登録する | 68000 と共通の命令実装を共有する | 追加命令と変更命令だけが 68010 handler を持つ | `test_68010`、`test_op_table` |
| VBR を例外ベクタの基底にする | 68010 の再配置可能なベクタテーブルを再現する | TRAP と IRQ のベクタ読出しが VBR 相対になる | `test_68010` |
| group 0 frame を format 8 とする | bus/address error の再開情報を保持する | RTE は format を検証して再開する | `test_68010`、`test_bus_error` |
| 命令開始時の状態を退避する | fault 後の命令再開で EA 副作用を残さない | postincrement、predecrement、MOVEM などを再実行できる | `test_68010` |

## 4. 構成とデータモデル

MC68010 は MC68000 の状態に VBR、SFC、DFC と命令再開用 snapshot を追加する。公開の
`mc68k_regs_t` は VBR、SFC、DFC を観測できる。

```text
命令境界
  ├─ D/A/SR の再開用 snapshot を保存
  ├─ 68010 opcode handler を実行
  └─ group 0 fault
       ├─ format 8 frame と再開情報を作成
       └─ RTE: format を検証し、retry 時は命令先頭へ復帰
```

再開 snapshot は内部状態であり、公開 API から直接操作しない。

## 5. インターフェース、レジスタ、入力

| 項目 | 契約 |
| --- | --- |
| VBR | 例外ベクタテーブルの基底。reset 時は 0 |
| SFC / DFC | MOVES の source / destination function code。下位 3 bit が有効 |
| MOVEC | SFC、DFC、USP、VBR を制御レジスタとして扱う |
| MOVES | SFC または DFC で選んだ function code により memory access する |
| RTD | stack を復帰して符号付き displacement を加算する |
| RTE | format 0 または format 8 frame を復帰する |

`mc68k_get_regs()` で VBR、SFC、DFC を含む snapshot を取得できる。MOVEC と MOVES は
特権命令であり、ユーザモードでは副作用より先に privilege violation となる。

## 6. 動作仕様

### 命令差分

MOVE from CCR、MOVEC、MOVES、RTD、BKPT は 68010 の decode table で扱う。MOVE from SR は
68010 では特権命令である。BKPT は opcode として認識するが、外部ハードウェアの
breakpoint acknowledge はモデル化しないため、ベクタ 4 へ配送する。

### 例外 frame と再開

通常例外と IRQ は format word を含む format 0 frame を使う。group 0 の bus error と
address error は format 8 frame を使う。RTE は frame format を検証し、未受理の format は
format error を発生させる。

format 8 frame の retry 指示がある場合、RTE は保存した命令開始時の状態を復元し、命令先頭から
実行を再開する。再実行中に同じ group 0 fault が繰り返される場合は、安全弁として CPU を halt
する。frame 作成中の fault は halt する。

通常例外、trace、IRQ のベクタ読出しが bus error になった場合は、その実行呼出しの中で vector 2
を配送する。このとき、例外を起こした命令は巻き戻さず、途中まで積んだ format 0 frame の下に
format 8 frame を積む。format 8 frame の saved SR/PC は例外発生時の値を使い、RTE はこの途中の
frame を含めて元のスタックへ戻す。handler が fault を解消せずに RTE して同じ vector 読出しを
再試行する場合、同じ命令 PC への復帰であれば安全弁により 2 回目に halt する。trace は命令完了後の
例外で PC が進むため、この安全弁では停止せず、vector 読出し fault を命令ごとに繰り返す。

### サイクル

68010 固有の命令、例外、RTE の cycle 値と、68000 から変更された基本値は model timing profile
で解決する。命令 handler は必要な実効アドレス cost を加算する。

## 8. 互換性と既知の制約

- 68010 の FPU、MMU、cache は構成・実装とも対象外である。
- BKPT の外部 breakpoint acknowledge サイクルはモデル化しない。
- group 0 retry は fault を解消した handler が RTE を実行する場合にだけ進行する。繰返し fault は
  安全弁により halt する。通常例外、trace、IRQ の vector 読出し fault は上記の vector 2 配送の
  対象だが、frame push の失敗は halt のままである。
- VBR は reset 時に 0 へ戻る。SFC と DFC も再現性のため 0 へ初期化する。
