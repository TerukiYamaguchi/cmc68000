# MC68000

## 1. 目的と対象範囲

この文書は `MC68K_MODEL_68000` の CPU 実行モデルを定義する。対象は MC68000 の
整数命令、実効アドレス、例外、割り込み、デコード、サイクル計算である。

外付け FPU、68010 以降で追加された命令・例外フレーム・MMU・cache は対象外とする。
`MC68K_FPU_NONE` 以外の FPU 構成は MC68000 モデルで生成できない。

## 2. 実装状態

MC68000 は既定の CPU モデルである。`mc68k_create(bus)` は
`mc68k_create_model(bus, MC68K_MODEL_68000)` と同じ構成を生成する。

公開 API は CPU の生成、reset、実行、IRQ 設定、TRAP hook、レジスタ snapshot を提供する。
メモリマップ、周辺機器、ホストの実行ループは利用側が実装する。

## 3. 設計の要点

| 決定 | 理由 | 影響 | 検証 |
| --- | --- | --- | --- |
| CPU 状態は不透明型にする | 内部実装との結合を防ぐ | 利用側は公開 API と `mc68k_regs_t` を使う | CPU API と各 CPU テスト |
| バスを callback 境界に置く | メモリ、I/O、DMA をライブラリの外で構成できる | CPU は memory map を持たない | `test_bus`、`test_bus_error` |
| 命令境界で実行予算を判定する | 命令の途中状態を公開しない | 実消費サイクルは予算を超えうる | `test_executed_cycles`、`test_cycle_golden` |
| 未登録 opcode は illegal instruction とする | モデル別の命令可用性を decode table で一元化する | 68010 以降の命令は 68000 で実行されない | `test_op_table`、`test_68010` |

## 4. 構成とデータモデル

CPU は D0–D7、A0–A7、PC、SR、USP、SSP を内部状態として持つ。A7 は SR の S bit に応じて
USP または SSP を指す。`mc68k_regs_t` はこれらを観測するための snapshot であり、CPU の
内部表現ではない。

```text
mc68k_execute()
  └─ 命令境界: IRQ 判定 → opcode fetch → decode → handler 実行
       ├─ ea_helpers.c: 実効アドレスと operand access
       ├─ cycles.c: 命令・EA の消費サイクル
       └─ 例外時: frame 作成 → ベクタ読出し → handler へ分岐
```

`mc68k_reset()` はアドレス `$000000` と `$000004` を long word として読み、SSP と PC を
設定する。D0–D7 と A0–A6 は reset 時にゼロクリアする。SR はスーパーバイザモード、
割り込みマスク 7 へ初期化する。

## 5. インターフェース、レジスタ、入力

| 項目 | 契約 |
| --- | --- |
| `mc68k_create()` | MC68000・FPU なしの CPU を生成する |
| `mc68k_reset()` | reset vector から SSP と PC を設定する |
| `mc68k_execute()` | 指定サイクル予算まで実行し、消費サイクル数を返す |
| `mc68k_set_irq()` | push/latch 型 IRQ level を更新する |
| `mc68k_bus_t` | 命令・データ・例外フレーム・ベクタの bus access を提供する |
| `mc68k_regs_t` | D/A、PC、SR、USP、SSP の snapshot を返す |

word と long の bus callback はビッグエンディアンの数値を受け渡す。read/write callback が
`false` を返すと bus error になる。詳細は [バス](../../integration/bus.md) を参照する。

## 6. 動作仕様

### 実効アドレス

実効アドレスの評価は `ea_helpers.c` に集約する。A7 の byte predecrement/postincrement は
2 byte 単位で更新し、その他のアドレスレジスタは operand size の分だけ更新する。68000 の
index extension は brief 形式だけを受理し、index scale は 1 とする。

奇数アドレスへの word/long access は bus callback の前に address error になる。

### 特権、例外、割り込み

特権命令は、状態や実効アドレスの副作用より先に privilege violation を発生させる。
通常例外は 6 byte frame、address error と bus error は 14 byte frame を使う。
例外 frame の作成またはベクタ読出し中に group 0 fault が発生した場合、CPU は halted state に
入る。

IRQ は命令境界でだけ受理する。受理可能な level は SR の割り込みマスクより高い level であり、
level 7 はマスクに関係なく受理する。IACK callback はベクタド割り込み、オートベクタ、
スプリアス割り込みを選択できる。

### デコードとサイクル

decode table は 65,536 個の opcode handler からなる。未登録 opcode は illegal instruction、
line A と line F は対応する line exception になる。各 handler は基本サイクルを返し、
`cycles.c` が MC68000 のサイクル値と実効アドレスの fetch cost を解決する。

## 7. 実装上の対応

| モジュール | 責務 |
| --- | --- |
| `src/cpu/m68000.c` | ライフサイクル、実行ループ、例外、IRQ、公開 CPU API |
| `src/cpu/decode.c` | opcode table の構築とモデル別 handler 登録 |
| `src/cpu/ea_helpers.c` | 実効アドレス、operand read/write、EA 制約 |
| `src/cpu/cycles.c` | 命令・実効アドレスのサイクル値 |
| `src/cpu/ops_*.c` | 整数命令、分岐、trap、system 命令の handler |

## 8. 互換性と既知の制約

- アドレスバス幅や未マップ領域の判定は bus 実装の責務である。
- MC68000 の FPU 構成は `MC68K_FPU_NONE` だけである。
- 68010 以降で導入された命令、VBR、MMU、cache、拡張例外 frame はこのモデルでは利用できない。
- cycle 値は命令単位の実行予算に使う。バス wait cycle は利用側が `access_timing` callback を
  実装した場合に加算される。

一致することである。
