# MC68030 / MC68EC030

## 1. 目的と対象範囲

`MC68K_MODEL_68030` と `MC68K_MODEL_68EC030` の、68020 から追加される PMMU または
access-control、translation cache、bus timing を定義する。

## 2. 実装状態

両モデルは 68020 命令を継承し、同じ cycle profile を使う。68030 は PMMU table walk を、
EC030 は AC0/AC1 と ACUSR による access-control を実装する。

## 3. 設計の要点

| 決定 | 理由 | 検証 |
| --- | --- | --- |
| PMMU opcode は専用モジュールへ集約する | translation の責務を整数命令から分離する | `test_68030_translate` |
| table walk は物理 bus access とする | 変換中に論理変換を再帰させない | `test_68030_mmu_boundaries` |
| EC030 は table walk を持たない | EC030 の access-control 構成を分離する | `test_68ec030` |

## 4. 構成とデータモデル

68030 は TC、CRP、SRP、TT0、TT1、MMUSR と translation cache を保持する。EC030 の公開 snapshot
では `tt0`／`tt1`／`mmusr` が AC0／AC1／ACUSR を表し、`tc`／`crp`／`srp` は 0 である。

## 5. インターフェース、レジスタ、入力

`mc68k_get_mmu_regs()` は PMMU または access-control の snapshot を返す。PLOAD、PFLUSH、
PTEST、PMOVE は 68030 PMMU の制御命令である。論理 access は function code、supervisor 状態、
read/write 属性を伴って translation に渡す。

## 6. 動作仕様

68030 の translation は transparent translation、ATC、table walk の順で処理する。table walk は
物理 bus access で descriptor を読み書きし、bus callback の wait cycle を実行 cycle に加算する。
EC030 は PMMU table walk を行わず、access-control register により可否と cache 属性を決定する。

## 7. 実装上の対応

| モジュール | 責務 |
| --- | --- |
| `ops_68030_mmu.c` | PMMU／access-control opcode、translation、ATC、table walk |
| `m68000.c` | logical access から translation の呼出し |
| `cycles.c` | 68030 cycle profile |

## 8. 互換性と既知の制約

68030/EC030 は同じ整数命令と cycle profile を共有するが、MMU 機能は異なる。68040 以降の
MMU、cache、例外 frame は対象外である。
