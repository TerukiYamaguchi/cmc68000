# MC68040 実装仕様

## 対象

MC68040 は `MC68K_MODEL_68040` で選択する。命令登録は基本命令、68010、68020、68030
の順に行った後、040 固有の MMU、cache、F-line handler を上書きする。

## MMU と cache

- MMU レジスタは `mc68k_get_mmu040_regs()` で観測できる。
- 変換は `ops_68040_mmu.c`、D-cache と CINV/CPUSH/MOVE16 は
  `ops_68040_cache.c` が担当する。
- `cpu_040_cache_read/write()` に届くアクセスは 1 個の 32-bit word に収まる前提である
  （`line_get()` と `cpu_040_cache_write()` が assert で検査する）。040 は非整列アクセスで
  address error にならず、アクセス関数が byte/word に分割してから呼ぶ。
- table-search の read は D-cache hit を利用するが、miss では line を割り当てない。
- `PFLUSH` と `PTEST` は 040 MMU handler が実装する。

## FPU

`MC68K_FPU_68040` は内蔵 FPU、`MC68K_FPU_NONE_040` は FPU を持たない 040 を表す。
後者の cpID 1 命令は通常の F-line 例外ではなく、040 の未実装 FPU 例外経路を使う。
040 FPU の命令実行と FSAVE/FRESTORE frame は `ops_fpu.c` にある。

## 例外と timing

040 の group 0 例外 frame は `m68000.c` が構築する。命令 timing は handler が返す
公称値に、必要な bus wait を加算する。pipeline overlap、cache-miss 転送時間の完全な
モデル化は行わない。

## データフォルトと WB2 保留ストア

040 の data access error は、format $7 のフレームで次の 2 通りに分ける（[040UM §8.4.6]）。

### 保留ストア（WB2）

命令ハンドラ実行中の単純な書き込みが ATC フォルトになったら、`cpu_translate_write_access()` が
`cpu->wb2`（論理アドレス・データ・access・変換結果）に保留して命令を最後まで実行する。
メモリへは書かない。`mc68k_execute()` が命令の後で `cpu_040_wb2_begin_delivery()` を呼び、
命令境界で access error にする。

- フレームの WB2S は V(bit7)・SIZE(6:5)・TT(4:3)・TM(2:0)。WB2A は論理アドレス、WB2D は
  書き込みデータ。TT は通常 00、MOVES は代替ファンクションコードなので 10
  （`TT_ALTERNATE`、`mc68k_access_t.alternate`）。
- 巻き戻さず、現在の SR と次の PC を積む（`g0_wb2_deferred`）。ハンドラが写像を直して RTE
  すれば、保留ストアはフレームの WB2 欄から書き戻される。
- SSW の TT も同じ値にする（`cpu_prepare_040_mmu_access_error()`）。

### 再実行（巻き戻し）モデル

次の場合は保留せず、命令開始時の状態へ戻して命令を積み直す。WB の各欄は無効のままで、
ハンドラが写像を直して RTE すると命令が最初から再実行される（`restore_restart_snapshot()`
が D0-D7/A0-A7 を戻す）。

- 2 回目の書き込み（`cpu_040_wb2_escalate()` が保留を捨てて再実行に切り替える）
- 読み出しフォルト、分割アクセス、RMW（TAS/CAS）、命令フェッチ
- 例外フレームの書き込み中、トレース中（CT を積まない）、MOVEM
- RTE の format $7 変換、FMOVE out の FP 例外後

MOVES のフォールバック経路（読み出しや host bus error）の SSW も TT=10 になる
（`group0_ssw_68040()`）。FPU のメモリ転送は An を自前で戻さず、この巻き戻しに任せる。
