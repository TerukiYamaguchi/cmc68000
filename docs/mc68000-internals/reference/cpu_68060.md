## 1. 目的とスコープ

MC68060 を生成時固定モデルとして追加する。派生 MC68LC060（FPU なし）、MC68EC060（FPU・paged MMU なし）は
`[060UM §1.1, App.A, App.B]` に従い、060 の構成差（FPU 有無・MMU 有無）として段階 2 で扱う。X68030/060turbo は
MC68060 搭載のため段階 1 は MC68060 のみ。

範囲: 整数部の 040 差分（未実装命令 trap、LPSTOP、PLPA、PCR/BUSCR）、MMU 差分、cache/branch cache、
例外フレーム `$4`、FPU の 060 差分、x68000 接続。命令時間（060UM §10 の表）は #102（§10.2）。

既知の非互換（実機と挙動が違うと分かっていて実装していないもの）。各項目の根拠と解決手順は §11 の表にある。
新しく見つけたら §11 に行を足し、本一覧にも 1 行足す。

- FSLW の RW=11: locked でない RMW（`ADD Dn,<ea>` 等）で read 側が RW=10、write 側が RW=01 になる。
- FSLW の SIZE=11 と TT=01: MOVE16 の bus error で出さない。FMOVE.D も SIZE=10 で出す。
- FSLW.BPE と TRAPF 拡張語による BPE 観測: 生成しない。
- ATC の no-allocate（TC.NAD/NAI）: 状態ビットの保持のみ。
- FOC/FIC（1/2-cache mode）の観測: 状態ビットの保持のみ。
- 040 の MOVE16 が `CACR.EDC` を見ない件: 040 側の Issue で扱う（060 は見る）。

## 3. モデルと述語

- `MC68K_MODEL_68060` は enum 末尾追加（040 追加後はその次）。x68000 の設定値との対応を崩さない。
- 述語: `cpu_is_68060()`、`cpu_has_68060_unimpl_int()`（vector 61 trap）、060 の内蔵 FPU 入口用の `cpu_has_060_fpu()` を追加する。
  `cpu_has_integrated_fpu()`（production では現在テストからしか使われていない）は 040 の F-line 入口の選択に使う予定で、060 では偽のまま（共有しない）。FPU の受理表は 060 専用表を持つ。`cpu_is_68040()` と `cpu_is_68030_family()` は 060 に拡張しない。
- 040 の MMU・cache・例外構築は共通基盤化（A〜D で実装される部品）し、060 差分は **フレーム構築・FSLW 生成・
  MOVEC 表・TC/CACR のマスク・branch cache・stack pointer の選択（SSP 1 本）・T0 trace の無効化・trace/割込みの受付タイミング・reset 初期化・RTE 受理表・line-F の特権判定・decode 登録（coproc 除外）・FPU 構成の受理・trace 抑止集合**として差し込む。差し込み点の正は 本書 §3.0 の表の全行である。
  040 の M=1 時の MSP/ISP 切替と throwaway `$1` を 060 へ流さない。040 の実装形に依存するため、
  共通化の切り口は、実装済みの 040 の部品に対する §3.0 の表の各行で固定する（残る未確定は 本書 §11）。

### 3.0 060 を黙って巻き込む／外す分岐（現行コードの機械抽出）

060 を enum 末尾へ足すと、(1) `>= MC68K_MODEL_68020`/`>= 68010`/`< 68020` の数値比較は 060 を**含み**、(2) `== MC68K_MODEL_68040` で 040 を先に

060 は**真側**に入る。(2) は 040 専用の frame・MOVEC・RTE・翻訳器が 060 で 020/030 の処理に変わるため特に危険である。

### 3.1 制御レジスタ（MOVEC `[060UM App.D MOVEC D-21/D-22, §3–§5, §7.4]`）

## 4. 未実装命令 trap（D1/D2）

- vector 61（format `$0`、stacked PC = 命令先頭）: `DIVU.L/DIVS.L` の 64bit 被除数形、`MULU.L/MULS.L` の 64bit 積形、
  `MOVEP`、`CHK2`、`CMP2`、`CAS2`、非整列 `CAS`。32bit 形の MULx/DIVx は実行する。
- vector 60（format `$0`）: FMOVEM.X 動的リスト、FMOVEM.L #imm 複数制御レジスタ、拡張/packed 即値 operand。
- vector 11: FP 未実装命令 `$2`、FP 無効（PCR.DFP/LC060/EC060）`$4`、未実装 F-line `$0`。各欄は 本書 §8.1。
- 他の例外との優先順位は 本書 §7（Table 8-3）に従う。
- 非整列 CAS の判定は EA の実値に依存するため、decode ではなく実行時に判定する（試験も実行時）。
- 試験で ISP 相当の最小 handler（テスト内ゲスト）を RAM に置き、vector 61 で代行実行→RTE の往復を検証する。
  trap しないことの回帰（040 以前のモデルが従来どおり直接実行する）も固定する。

## 5. MMU

040 MMU（URP/SRP/TC/TTR、ATC、descriptor 形式）の上位互換に近いが、以下を差分とする。

- MMUSR・PTEST を持たない。**PLPA**（PLPAR/PLPAW）を追加: ATC hit かつ権限が合えば物理アドレスを返し、miss なら table search。
  成功時は ATC へ load。無効 descriptor・write protect・bus error・supervisor 違反は**戻り値でなく access error 例外**
  （`[060UM §4.7.3]`）。PLPAR/PLPAW は read/write アクセスとして権限・履歴 bit を更新する。
- PLPA の符号化は `1111 0101 1 R/W 001 rrr`（R/W: 0=write, 1=read）。PLPAW=`$F588+n`、PLPAR=`$F5C8+n`（`[060UM App.D D-23/D-24]`）。
  FC は DFC。(1) data TTR hit: その TTR で変換し **An を変えない**。(2) TC.E=0 または MDIS: 既定 TTR（TC の DCO/DUO/DWO 等）で変換し **An を変えない**。
  (3) E=1 かつ data ATC hit / table search 成功: An=物理アドレス（`[060UM D-23]`）。特権命令（user は privilege violation）。
- PFLUSH 系は PFLUSH/PFLUSHA/PFLUSHN/PFLUSHAN（040 と同じ四形式、`[060UM §4.7.2]`）。符号化 `1111 0101 000 opmode rrr`
  （D-26 の図。ただし同頁は EC060 の頁で、opmode は 060/LC060 で定義と注記）。opmode の値表は 060UM になく、D-1 前書き（040 の記述は別記なき限り 060 に適用）により `[PM]`（040 の PFLUSH 表）を適用する: 00=PFLUSHN、01=PFLUSH、10=PFLUSHAN、11=PFLUSHA
  → `$F500+n`/`$F508+n`/`$F510`/`$F518`（A 系の register 欄は無視する: `$F510–$F517`/`$F518–$F51F`。040 の実装に合わせた選択で、PM に register 欄の制約は記載がない）。
- 060 の PFLUSH (An)/PFLUSHN は DFC の FC2 で user/supervisor の空間を選び、同じ論理ページでも反対空間の entry は消さない（PM p.6-35）。040 の entry は fc を完全な値（1/2/5/6）で持つが、060 の ATC tag は FC2 だけなので、flush と lookup の空間の比較は FC2 だけで行う（`[060UM p.4-25 Fig.4-20、p.4-26]`。SFC/DFC の 2/6 は Table 4-2 で 1/5 に変換される）。HEAD の 040 の `atc040_flush()` は FC を見ず両空間の同じページを消すので、この flush 関数は流用しない（T-B1 が落とす）。
- 失敗した table search は無効 ATC entry を作らない（PFLUSH 不要）。W=1 の ATC entry への書込みは、M の更新 walk より先に access error とし entry を変えない（`[060UM §4.2.6.3 p.4-22]`）。
- FSLW の PTA/PTB/IL/PF/SP/WP/TWE/TTR で原因を報告（PTEST の代替）。
- TTR は E/S/U1-U0/CM[1:0]/W、base/mask 各 8bit（`[060UM §4.1.3]`）。CM は 00 WT、01 CB、10 CI precise、11 CI imprecise。
  040 とは CM の**意味**が異なる（060 は厳密な program order で、CI は直列化。`[060UM §11.1.2.5]`）。ビット配置は同一。
- TC.E=0 でも既定 TTR 属性（DCO/DUO/DWO/DCI/DUI）で cacheability・保護が決まる。
- **命令フェッチの ATC 変換省略（高速経路、ゲストから観測できない内部最適化、#125）**: `cpu_translate_execute_access_060()` で、instruction・read・非 alternate・非 RMW のアクセスに限り、`cpu_mmu060_ifast_try()` が直近に ATC で解決した命令側 entry を先に試す。使用条件は (1) 前回と同じ FC2・同じ logical page・同じ page_shift、(2) TC・ITT0・ITT1 が前回の変換時と同じ値、(3) 記憶した slot の entry が今も `valid` で fc の S bit・`page_shift`・`logical_page` が一致、のすべて。ただし FC2・logical page は毎フェッチ確認し、(2)(3) の再検証は、記憶時の世代 `atc060_ifast.gen` が `cpu->ifast_gen` と違うときだけ行う（通れば世代を更新、#267）。世代は `cpu_ifetch_fast_invalidate()` で進める。呼ぶのは MOVEC 書込み（060）、ATC entry の置換、PFLUSH、`mc68k_reset` の TC・ITT 書換え、snapshot 復元。`ifast_gen` は snapshot の除外範囲に入れ、復元で戻さない（戻ると古い記憶が世代一致で通る）。試験が ATC・TC・ITT を直接書き換えるときも、書換え後に `cpu_ifetch_fast_invalidate()` を呼ぶ。TTR の範囲は 16MB 単位でページより粗いので、同じ page・同じ S なら TTR 判定と TC.E の再評価は要らず、(2) の値比較で足りる。URP/SRP・DTT・CACR は命令側の ATC ヒットに影響しないので比較しない（URP/SRP の変更で ATC は消えない）。不変条件: 結果（物理アドレス・cache mode・cache inhibit）はコピーを持たず毎回 entry から読む。ヒット時は通常経路と同じく `history = ++atc060_clock` を行い、LRU の挙動を変えない。slot は添字で持つ（snapshot の memcpy でポインタが別インスタンスを指さないため）。記憶の更新は EXECUTE の変換が ATC 由来（ATC ヒットまたは walk）で成功したときだけ行い、DEBUG 変換からは行わない。試験は `test_68060_ifetch_fast`（高速経路あり/なしで命令ごとの PC・D0・サイクル・ATC の内容・`atc060_clock` を比較）。
- **命令側ラインの高速経路（ゲストから観測できない内部最適化、#129）**: `cpu_fetch_word()` の先頭で `cpu_060_ifetch_fast()`（`cpu_internal.h`、inline）を試す。通常経路（`cpu_read_word_access` から変換、`cpu_040_cache_read` へ続く流れ）が命令側ヒットのとき行う処理を、1 回の inline で済ませる。使用条件は (1) 060、`atc060_ifast_disable`・`ifetch_fast_disable`・BADADDR ログ・group-0 フォルト保留中がいずれも偽、(2) 上の ifast 条件（FC2・logical page・TC・ITT0/1・ATC entry）が成り立ち、entry の cache mode が 2 未満（CACR.IE=1 のとき）、(3) CACR.IE=1 のとき、`icache040_last`（命令側で直近にヒットまたは充填したラインの平坦な添字）が指すラインが `valid`・`loaded` で、`physical_line` が今の物理ラインと一致（外れたときは、同じセットの 4 ウェイを探し、`cache_line()` と同じく最初に `valid` で物理ラインが一致するウェイが `loaded` なら、`icache040_last` をそれに更新してそのラインから返す。`loaded` でなければ通常経路が充填する。#134）、のすべて。1 つでも外れたら通常経路に任せる。CACR.IE=0 のときは (3) の代わりに `cpu_060_ifetch_nocache()`（`m68000.c`、外部関数）が、通常経路が ATC ヒット後に行う処理（`cpu_note_access`、`history`、`access_cache_mode`、`access_tt_hit`、バス読出し、待ち時間の計上、バスエラー）を 1 回の呼び出しで行う（#134）。IE=0 は 060turbo の既定で、BENCH の命令フェッチの 99.7% がこちらだった。不変条件: 副作用は通常経路と同じで、`cpu_note_access`、ATC の `history = ++atc060_clock`、`access_cache_mode`、`access_tt_hit` を更新する。ライン側の記憶位置は古くても結果が変わらない（毎回 (3) で検証する）ので、CINV/CPUSH・ライン置換で無効化は不要（ATC 側の記憶の無効化は上の世代で行う）。記憶位置の更新は `cpu_040_cache_read` が命令側のラインを返すときだけ行う。ループが 2 本のラインをまたぐと、ラインの先頭語は通常経路になり、2 語目以降が高速経路になる。試験は `test_68060_ifetch_line`（高速経路あり/なしで命令ごとの PC・D0/D1・サイクル・ATC・I-cache 全ライン・フォルト記録を比較、CINV 各種・CACR.IE 切替・ライン無効化と置換・noncachable・PFLUSH・TC/ITT・S/U 切替・別ページへの分岐。高速経路が働くことは重複ラインで確認）。
- **データアクセスの ATC ヒット高速経路（ゲストから観測できない内部最適化、#128）**: `cpu_translate_execute_access()`（inline）が 060 のとき、本体を呼ぶ前に `cpu_mmu060_dfast_try()` を試す。構造体を返さず `physical`・`cache_inhibit` を直接返す。キーは保存せず、毎回その場で次を判定する: 非 instruction・非 alternate、TC.E=1、DTT0/DTT1 の E がどちらも 0、`atc060_hint[0][(logical>>ps)&15]` の slot の entry が `valid`・fc の S bit・`page_shift`・`logical_page` と一致。write（`!read || rmw`。TAS/CAS の read 部を含む）は entry が `W=0` かつ `M=1` のときだけ使い、WP フォルトと M 更新の walk は必ず通常経路に落とす（フォルト順序 WP→M は不変）。hint 表は通常経路が全探索したときだけ更新し、高速経路では更新しない（通常経路の hint ヒット時と同じ）。成功時は通常経路と同じく `history = ++atc060_clock`、`access_cache_mode` の設定、`access_tt_hit = false`（FSLW.TTR に使う）を行う。`modified`/`write_protect` は使うたびに entry から読む。PFLUSH は `valid=false` にするだけなので entry 検証で検出でき、PLPA は別の呼び出し元なので影響しない。無効化スイッチは `atc060_dfast_disable`（試験用）。試験は `test_68060_data_fast`（高速経路あり/なしで命令ごとの PC・D1/D2・サイクル・ベクタ・D 側 ATC（history・W・M 含む）・hint 表・`atc060_clock`・RAM 全体を比較。M/W/RMW/page_shift/S/valid/history/`access_tt_hit` を抜いた変異が検出されることを確認済み）。
- debug translate は 060 では legacy `mmusr`=0。MMUSR 相当を持たないため snapshot API は 040 より小さい。

## 6. キャッシュ

- 8KB I + 8KB D、branch cache。CACR は 040 の DE/IE と同位置に EDC/EIC を置き、ビットを追加（本書 §2）。cache 関連の reset 初期化は CACR のみ（tag・データ・状態は保持するので CINVA が前提。060UM §5.2/§5.3）。
- CINV は `1111 0100 cc 0 ss rrr`、CPUSH は `1111 0100 cc 1 ss rrr`（bit5 が CINV=0/CPUSH=1）。cc=00 は NOP、ss=00 は **illegal instruction**
  （CPUSH は `[060UM D-12]`、CINV は D-1 前書きにより `[PM]` の 040 CINV 頁を適用）。
  I-cache 対象の CINV/CPUSH は branch cache も自動で無効化する（060UM §5.11）。
- ロックされたアクセス（TAS/CAS オペランド、table search の history 更新）は常に precise（`[060UM §5.4.2]`）。
- TAS/CAS と BUSCR.L 中のオペランド参照は、miss でも D-cache に allocate せず bypass する（`[060UM §5.1]`）。hit した行は valid なら invalidate、
  dirty なら push+invalidate してから bypass（原文の主語は CAS/TAS。BUSCR.L 中の hit 動作は同節からの**推論**）。BUSCR.L 中のアクセスが precise になるという記述は原文にない。
- MOVE16 は D-cache に allocate しない。read hit は cache から、write hit は該当行を invalidate して外部書込（`[060UM §5.4.3]`）。
  例外 stack/vector fetch と table search も allocate しない。
- CINV/CPUSH の An は物理アドレスで、MMU で変換しない（CPUSH は `[060UM D-11]` の「matching the physical address in the specified address register」、CINV は PM p.6-3 の CINVL を D-1 前書きで適用）。T-D1 の CINV も論理≠物理にマップして試す。
- CPUSH は DPI=0 で push+invalidate、DPI=1 で push のみ（dirty line について。clean line の DPI=1 は一次資料が食い違うため固定しない、本書 §11）。CPUSH 命令の I-cache 指定は CINV 扱い。
- branch cache は論理 cache のため、MMU 再マップ時は CACR.CABC（全体）/CUBC（user のみ）で無効化（`[060UM §11.1.2.3]`）。
  観測可能性は「CACR 書込でビットが 0 読みになる」点と、無効化しなくても結果が変わらないこと（分岐予測は
  アーキ可視でない）に限る。**branch cache の予測挙動そのものはモデル化しない。**
- store buffer（ESB）、1/2-cache mode は状態ビットの保持のみ。観測可能な副作用（imprecise write の遅延）は
  060-D で、040 の `cpu_040_cache_write`（`cache_mode` を受ける）に 060 用述語を通してから扱う。

## 7. 例外と RTE

- アクセスエラーは format `$4`、vector 2。FSLW 各ビットの設定規則は `[060UM §8.4.4.3]` を word 単位 fixture 化。生成しないビットと符号化は §1 末尾の既知の非互換一覧と §11 を参照。
  fault address は論理アドレス。非整列は最初のアクセスのアドレス。拡張語 fault は命令 opword のアドレス。
- 優先順位（`[060UM Table 8-3]`、小さいほど高い）: Address Error 1.0 > 命令 access error 1.1 > データ access error 1.2 >
  A-line 2.0 > F-line 未実装 2.1 > Illegal 2.2 > Privilege 2.3 > 未実装 EA 2.4 > 未実装整数 2.5 > FP 未実装/非対応データ型 2.6 >
  FP BSUN/CHK/CHK2/DIVZ/TRAPV/TRAPcc/TRAP/RTE format error 3.0 > FP SNAN〜INEX 3.1–3.6 > Trace 4.0 > Interrupt 4.1。
- ISP が CHK2/FTRAPcc を代行して発生させる例外は format `$2`（`[060UM §8.4.2]`）。address error も `$2`（address 欄に分岐先、A0=0）。
- RTE は `$0/$2/$3/$4` を受理し、`$4` は SR/PC のみ復帰（restart。write-back なし）。その他は format error（vector 14）。
  040 の `$7`、030 の `$A/$B` は format error。
- bus error on write の「喪失」ケース（push/store buffer、imprecise）は PC が fault 命令を指さない（`[060UM §8.4.4.1]`）。
  precise/imprecise の区別は cache mode（CM）に依存するため、040 の `access_cache_mode`（TTR/ATC の CM から決まる）を 060 でも使う 060-D で扱う。
- RTE は stack の format（SP+6）を先に検証し、無効なら format error。次に PC が奇数なら address error。どちらも新 frame の SR は RTE 実行前の値、
  PC は RTE 命令を指す。RTE は access error frame を他の frame と区別しない（`[060UM §8.4]`）。
- address error はインストラクション prefetch の奇数アドレス（分岐先、RTS/RTR/RTD/RTE の PC、奇数 vector）だけで、
  **データ非整列は例外にならない**（`[060UM §7.6]`: "does not enforce any alignment restrictions for data operands"。address error は奇数 prefetch だけ、§8.2.2）。
  FSLW.MA は、別原因の fault が非整列転送の 2 回目以降のアクセスで起きたことを示すだけ（§8.4.4.3）。非整列 CAS は vector 61（本書 §4）。
  vector 12（Emulator Interrupt）は debug pipe control mode（§9.2.3 Emulator Mode）をモデル化しないため生成しない（`[060UM Table 8-1]`）。FSLW.SEE は CPU が立てない（060SP 用）。
- branch prediction error（BPE）は FSLW.BPE を立てる fault だが、branch cache をモデル化しないため**生成しない**。

- 試験（記号は 本書 §10.1 の試験 ID と対応）: (a)=T-C5。(a) trace 中に TRAP を実行しても trace frame が出ない。(b)=T-C6。(b) 例外 handler 先頭で `MOVE #$2700,SR` を実行すると、保留中の level 1–6 割込みが受け付けられない（level 7 は mask 不可・遷移検出のため対象外、§8.2.9）。
  (c)=T-C4。(c) `MOVE #$3000,SR`（M を 0→1）の前後で A7 が変わらず、割込みで積まれる frame は SSP−8 に置かれ（SSP 1 本）、SR の M=0 になり、積んだ SR には元の M=1 が残り、その RTE で M=1 に戻しても A7 は SSP のまま（`[060UM §11.1.2]`）。
  (d)=T-C5。(d) group 3 の例外を trace 中に各 1 件実行し trace frame が出ない: CHK、DIVU/DIVS のゼロ除算、TRAPV、TRAPcc（3 形式）、RTE format error（FP の group 3 は T-E3）。
  抑止集合は `exc_vector_suppresses_trace()`（`m68000.c`）。060 以外は vector 4/8/9/10/11（ILLEGAL/特権違反/trace/A-line/F-line）だけで、TRAP/TRAPV/CHK/ゼロ除算は抑止しない。060 は 5/6/7/14/32–55 と 60/61 を加える。(a)(d) は 060 の集合から group 3 を落とす変異を検出する。
  (d')=T-A5（vector 61）、T-E4（vector 60）。trace 中の MOVEP または CHK2（vector 61）で trace frame が出ない（060 で group 2 に加わる。抑止集合に足し忘れる変異を検出）。
  vector 60 は FP 命令（拡張/packed 即値、FMOVEM.L #imm の複数制御レジスタ、FMOVEM.X 動的リスト。`[060UM §8.2.4, §6.5.3]`）でしか起きないため FP の decode を要し、060-E に置く。
  FP Unimplemented（vector 11 / `$2`）・Unsupported Data Type（55）・BSUN（48）・算術例外（49–54）の trace 抑止は T-E3。
  (e)=T-C5。(e) SR の T1=0・T0=1 を書いて分岐しても trace frame が出ない（change-of-flow trace なし、`[060UM §11.1.2.4]`）。期待値は T0 が保持されるか（本書 §11）に依らない。

#### 7.0 実装（060-C）

- access error / address error の frame は `deliver_group0_exception_68060`（`m68000.c`）。020 の `$A/$B` builder と 040 の `$7` builder には落とさない。命令開始時のレジスタへ巻き戻して命令の先頭 PC を積む（restart）。通常 frame を積む途中の fault は exception frame origin の SR/PC を積み、RTE は `cpu_exception_frame_origin_rte_commit` で復帰する（HALT か access error かは §11 のとおり固定しない。現行の 020/030 と同じく access error）。
- FSLW は fault 時の属性から `group0_fslw_68060` が組み立てる。MMU の失敗（`g0_mmu_result`）は `cpu_translate_execute_access_060` が保持する。fault address は最初の論理アドレス（分割アクセスの `origin`）、拡張語の fault は命令 opword のアドレス。
- address error は prefetch の奇数アドレスだけ。奇数の分岐先（JMP/JSR/BRA/RTS/RTR/RTD など）は、分岐命令の完了後に `execute_body` が検出し、分岐命令の PC と完了後の SR を積む（巻き戻さない）。RTE の奇数 PC は frame の format 検証の次に検出し、RTE 実行前の状態を積む。例外処理で奇数 vector に入った場合は次の命令 fetch で検出し、stacked PC はその奇数 PC になる（実機の値は未確認）。
- `irq_defer`: 例外処理の完了（`cpu_exception_frame_origin_complete` と 060 の group 0 builder）で立て、`execute_body` の次の命令境界で 1 回だけ割込みの判定を飛ばす。level 7 も同じく遅らせる（実機の NMI の扱いは未確認）。
- BUSCR: `buscr_save_for_exception` を `accept_irq`・`cpu_dispatch_exception`・060 の group 0 builder から呼ぶ。SL/SLE は原文どおり L/LE の写し（§11 の SLE の記述の食い違いは未解決）。

### 7.1 特権命令（`[060UM §8.2.5]` の列挙 18 項目の全件）

user モードで実行すると、いずれも副作用より先に privilege violation（vector 8、format `$0`、stacked PC = 命令の第 1 語、`[060UM §8.2.5]`）になる。
下表の「不変とする状態」は、user モードで実行した後に実行前と一致することを、試験列の試験が固定する。ATC・cache・FPU に依らない行は T-A10（060-A）、PFLUSH/PLPA は T-B6（060-B）、CINV/CPUSH は T-D3（060-D）、FSAVE/FRESTORE は T-E6（060-E）で、その状態が 060-A の時点で存在しない行を 060-A に課さないよう Issue ごとに分ける。各試験は user と supervisor の両方で実行し、supervisor では例外にならず本来の動作をすることも確かめる（特権検査を全モードに掛ける変異を検出する）。**実行前の状態は、命令が実行されれば変わる値にする**（変わらない状態では「副作用を検査より先に行う」変異が生き残るため。各試験の前提状態を T-B6/T-D3/T-E6/T-A10 に書く）。試験列のうち T-A6/T-B1/T-D1/T-E2/T-A3 は本来の動作の関連試験で、user の不変は T-A10/T-B6/T-D3/T-E6 が固定する。

| MOVEC | Cr（BUSCR は事前値 0 で）と Rn（有効な Cr 14 個の全部で実行）。未定義 Cr の user 実行は illegal（2.2）と privilege（2.3）の優先順位が一次資料の例示にないため固定しない（本書 §11） | T-A10、T-A3 |

## 8. FPU

- 共通 FPU コアのうち 060 が実装する命令だけを受理する。Table 6-11 の Monadic 22・Dyadic 3・Miscellaneous 3（計 28 項目）は vector 11 / `$2`、同表の Unimplemented Effective Address 4 項目（FMOVEM.X 動的リスト、FMOVEM.L #imm の 2〜3 制御レジスタ、F<op>.X #imm、F<op>.P #imm）は vector 60 / `$0`（§6.5.3）として扱う。FSAVE/FRESTORE は 3 long word frame。
- `design_fpu_4.md`（040 内蔵）の受理表と別に 060 受理表を持つ。**040 の表から削って作らない**（060 だけが実装する FINT/FINTRZ があり、040 実装の FDBcc/FScc/FTRAPcc は 060 で vector 11 になる。`[060UM Table D-1, Table 6-11]`）。FSAVE frame は 040 と相互復元不可扱い（本書 §2）。
- FP 例外 vector/frame（`[060UM Table 6-10]`）: 11=`$2`、55=`$0/$2/$3`、60=`$0`、48(BSUN)=`$0`、49(INEX)=`$0/$3`、50(DZ)=`$0`、
  51(UNFL)/52(OPERR)/53(OVFL)/54(SNAN)=`$0/$3`。（同表は vector 60 の offset を `0F4` と印字するが、Table 8-1 の `0F0` が正）
- FP disabled（PCR.DFP=1、LC/EC060）は vector 11 / `$4`。各欄は下表（本書 §8.1）。
- 詳細は FPU-6（新規）で設計する。

FP disabled の条件は §6.5.1/§8.2.4 の対比で決まる（§6.5.1 は PCR を "processor control register"、§8.2.4 は "processor configuration register" と呼ぶ。未サポートデータ型の PCR 条件の出典は §8.2.4 のみ）: FP 未実装・未サポートデータ型は「FPU が PCR で有効」を条件に含み、FP disabled は FPU が無効のとき。
したがって DFP=1 では Table 6-11 の命令も vector 11 / `$4` になる（未実装表の判定を DFP の判定より先に行わない）。

FP disabled の SP+8（EA 欄）: メモリオペランドなら EA、レジスタオペランド（FPn・Dn）なら `$0`。#imm とオペランドなし（FNOP、FBcc、FMOVECR 等）の値は規定がなく固定しない。
(An)+ と −(An) では **An を更新しない**。−(An) では「最初のメモリオペランドのアドレス」で、拡張精度だけは An−12 でなく **An−4**（§8.2.4）。
拡張精度以外のサイズの値を An−size（B=1, W=2, L=S=4, D=8）とするのは「最初のメモリオペランドのアドレス」からの**推論**で、A7 の .B は 2 byte ずつ動く
（`sp_byte_step()`）ので試験で A7 を使わない。packed（.P、12 byte）は原文に規定がなく 本書 §11 に残す（固定しない）。FP 未実装命令（`$2`）で (An)+/−(An) のとき An が更新されるかも原文にない（本書 §11、固定しない）。

## 9. x68000 接続

- `cpu_model=68060` / `-cpu-model 68060`。060turbo はアドレス幅・メモリ配置が X68030 + ローカル RAM のため、
  040 設計書 §8 と同じく「X68000 バスに 060 コアを接続する開発構成」とし、実機同等は主張しない。
- 060turbo.sys の起動を受入基準にする（ISP/FPSP の vector 61/60/11 動作、MMU によるメモリ配置、cache 制御）。
  ただしソース/バイナリの再配布条件は転載可（X68000 LIBRARY）。ISP/FPSP は Motorola 060SP 由来のためゲスト側に任せ、
  リポジトリへは同梱しない。

### 10.2 命令時間の実装（#102、T-G1）

- 実装: `src/cpu/timing_060.c`。`mc68k_execute()` が handler の戻り値を `cyc060_instruction()` で置き換える。例外を積んだ命令は `cyc060_exception()`（Table 10-26）の値を使い、置換しない。割り込みの受付は `accept_irq_body` が `cyc060_interrupt()`（Table 10-26 注 3、ベクタ番号によらず 23）を返す。分岐の taken は handler が立てる `flow_changed` で判定する（変位が次の命令を指す場合も taken）。`CYC_PROF_68060` は handler が参照する class を [060UM §10] の値で固定し、040 以前の行へ暗黙に落とさない。
- 値の出典: Table 10-5（EA 計算）、10-6〜10-8（MOVE）、10-9〜10-13（標準・immediate・単一オペランド・shift・bit）、10-14〜10-16（bit/bit field）、10-17〜10-19（分岐・JMP/JSR・RTS 系）、10-20〜10-21、10-22〜10-24（SR・MOVEC・その他）、10-25（FPU）、10-26（例外）。
- 簡略化・固定した値:
  - 分岐は 256 entry direct-mapped の branch cache（taken で登録、not taken で削除する 2 状態）で、未登録＝静的予測列、登録済み＝予測成功/失敗列を選ぶ。060 の 5 状態予測・4-way・予測 not taken 列は模さない。CACR の EBC=0 なら常に静的予測列。CABC/CUBC と instruction cache 対象の CINV/CPUSH で消える。
  - 予測成功の分岐は表が 0 cycle（畳み込み）だが、`mc68k_execute()` が 0 cycle の命令で進まなくなるため 1 cycle に切り上げる。
  - CINV は Table 10-24 の上限値（「≦」）、MOVE16 は cache miss の 18、PLPA は ATC hit の 15、word divide は上限の 22 を使う。
  - CPUSH は上限値を固定で課さず、「基準時間 + 10 × 実際に書き戻した dirty line 数」で数える（`cyc060_cache_op`、line 数は `op_cache060` が `t060_aux` に積む）。表（CPUSHA ≦5394(0/512)・CPUSHP ≦2838(0/256)・CPUSHL ≦26(0/1)）は上限だけを印字するため、基準時間（CPUSHA 274・CPUSHP 278・CPUSHL 16）と line 単価 10 は 3 点から逆算した**推定値**で、表の line 数で上限値に一致する。dirty line がなければ基準時間だけになる（実機の値は一次資料にない）。固定の上限値は、Human68k の 060 用ドライバのようにデバイス要求ごとに CPUSHA を実行するゲストでは、クリーンな cache の CPUSHA 1 回が約 20 倍（5394 対 274）に課金される。これが ix68k の `drive a: b:` を約 8 秒にした一因。bus wait は従来どおり別に加わる。
  - FPU は Table 10-25 の opmode ごとの基本値に、ソース形式（byte/word/long +3、extended +2）、Dn 直接 +2、EA 加算を足す。
- 基準命令時間に含めない要因（別 Issue）: instruction/data cache miss、ATC miss と table walk、copyback の write-back、バス wait、dual issue の重なり、change/use stall、OEP と IFP の待ち（[060UM §10.2、§10.3]）。ここへ足すときは `cyc060_instruction()` の戻り値に加算する境界とする。
- CSV 契約（T-G2、`tools/check_68060_cycle_data.py` が `test_68060_cycle_data`、`test_68060_timing_expect` が実行結果を検査する）:
  - `tests/data/cpu/mc68060_cycle_raw.csv`: [060UM §10] の Table 10-1〜10-26 の印字値を 1 セル 1 行（1,201 行）。`projection` は `nominal`（印字値）、`upper-bound`（「≦」）、`not-modeled`（基準命令時間に含めない／模さない。`note` に `reason=` と `actual=` が必須）。`per_unit` は MOVEM／FMOVEM の `n` 倍の係数。
  - `tests/data/cpu/mc68060_cycle_classification.csv`: raw 行を `(table, instruction, condition)`（condition `*` は命令全体）で分類する。`disposition` は `inherit-040`／`override`／`unimplemented-vector-61`／`out-of-scope`。`implementation` は `file:function`（存在を機械検査）。未分類の raw 行、raw 行に当たらない分類行、`not-modeled` の raw 行が `out-of-scope` 以外、時間を持つ raw 行が `out-of-scope` のどれも検査で落ちる。
  - `tests/data/cpu/mc68060_cycle_expectations.csv`: 2,036 行（.W の主表に加え、.B 版、ビットフィールドの 5 byte 境界、FPU の memory indirect、表の脚注の両側の条件を含む）。branch cache の遷移（CUBC は user の entry だけ、IC を対象にする CINV と CPUSH、DC だけの CINV は消さない、CACR の読み出しと CACR 以外の MOVEC は消さない、CABC が CUBC に優先、EBC=0 では使わず登録もしない、予測失敗での削除）は `test_68060_timing`。割り込みの期待行は setup の `irq=<level>`・`iack=<vector>`（IACK が返すベクタ番号。省略は autovector）で、ベクタ番号によらず 23。命令語列（`/` 区切りで最後の 1 命令を測る）と setup から `expected_cycles` を出す。`expected_cycles = raw.cycles + raw.per_unit × n + adjust` を検査し、`adjust` が 0 でなければ `adjust_reason` が必須。全ての時間を持つ raw 行に 1 行以上の期待行がなければ落ちる。

- FP Unimplemented Data Type（vector 55）は `nominal` の行。期待行は非正規化数のソース（pre-instruction、format `$0`）の後の FP 命令で測る。packed は `FMOVE.P <ea>,FP0` が受理され次の FP 命令で、`FMOVE.P FP0,<ea>` がその場で vector 55 になる。
- 印字値の解釈: (1) Trace は推論: [060UM §10.16] は「原因の命令の OEP 時間を含む」とするが、トレースされた命令と 19 の合成は規定がない。現実装は命令の時間に 19 を足す（期待行は 19 + 1、`adjust_reason` に推論と明記）。(1c) MOVEM の `n == 0` を 1 register として数えるのは推論（一次資料に根拠がない。表の範囲外）。(1b) ビットフィールドの Dn の列の「= 5 Bytes」は、一次資料が Dn の field が 5 byte になる条件を定めていないため、memory と同じ `off%8 + width > 32` を使う推論。(2) Table 10-25 の FINT／FINTRZ（Dn は +1、(d8,An,Xi)・absolute・#<data> は +0、(bd,An,Xi) は +2）、FSUB 系と FTST の #<data>（+0）は他の命令と加算が違うが、印字値どおりに実装した（誤植の可能性は他に一次資料がなく判断できない）。(3) 浮動小数点の例外（INEX2／DZ／UNFL／OPERR／OVFL／SNAN）は保留され、次の FP 命令の実行時に 19 で受理される（`fpu->exc.valid`、[060UM §6.7]）。期待行は原因の命令の後に FMOVE FP0,FP0 を置いて測る。
- 表の突き合わせで見つかった実装の不具合（修正済み）: CMPA の (Ay)+／-(Ay) で Ay = An の +1（Table 10-9 注 1）が抜けていた／ 静的ビット数の BSET（`$08C0`）を CAS と取り違えて 19 cycle にしていた／STOP・LPSTOP が handler の 4 cycle のままだった（表は 8・15）／ビットフィールドの Dn の列に =5 Bytes が効いていなかった／バスエラー（data fault）の handler の早期戻り値 4 を捨てず 23 cycle になっていた（表は 19）／FPU の丸め精度つき opmode（FSADD・FDMOVE・FSSQRT など）が基本演算に戻らず別の演算の時間になっていた／FMOVE ,FPCR・FPCR, の (d8,An,Xi)・absolute・#<data> の加算漏れ／PEA の (bd,PC,Xi) のメモリ間接に +2 が抜けていた（Table 10-20 注 1、2 → 4）／ベクタ割り込み（autovector 以外のベクタ番号）が 23 でなく 19 になっていた（Table 10-26 注 3）／変位が次の命令を指す taken の Bcc・BSR・DBcc・FBcc を not taken と判定していた（Table 10-17）。
- ix68k での確認: IPLROM 1.6 の MPU クロック測定が `cpu_clock=50` で `50.0MHz` と表示される（020 行を使っていた時は 8.3MHz）。
